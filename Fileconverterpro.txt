7. SECURITY SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Authentication & Session
  ─ JWT access tokens (15min, memory only)
  ─ Refresh tokens (7 days, httpOnly cookie, rotated on use)
  ─ JTI — unique session ID, allows per-session revocation
  ─ bcrypt password hashing (salt rounds 10)
  ─ Google OAuth with provider conflict detection
  ─ WebAuthn Passkeys — biometric/PIN, replay counter, duplicate device blocked
  ─ passwordChangedAt invalidates old tokens instantly
  ─ Session list + revocation in user dashboard
  ─ Logout all devices

  Bot & Abuse Protection
  ─ reCAPTCHA v3 on signup, login, forgot-password (threshold 0.7)
  ─ Rate limiting on every route (per-user ID or per-IP)

  HTTP & Network
  ─ Helmet.js — 10+ security headers
  ─ HSTS 2 years (includeSubDomains + preload)
  ─ Strict Content Security Policy
  ─ CORS strict origin whitelist
  ─ Express fingerprint hidden
  ─ Request ID on every request (UUID)
  ─ Trust proxy correctly configured

  File Security
  ─ Magic byte MIME validation (fileTypeFromBuffer)
  ─ MIME vs extension mismatch check
  ─ Filename sanitization
  ─ SVG blocked as upload input
  ─ File size limits on body + files
  ─ Strict MIME whitelist (video/audio/image/pdf only)

  AI Security (Prompt Injection)
  ─ Forbidden pattern regex list (prompt injection, SQL, XSS)
  ─ Input sanitization (zero-width chars, Unicode, emojis)
  ─ Character/word/page/size limits on AI inputs
  ─ AI response sanitization (strips HTML/script tags)
  ─ System prompt restricts chatbot to website context only
  ─ Low temperature on both models (reduces hallucination)

  AI Microservice Security
  ─ INTERNAL_API_KEY shared secret (backend ↔ microservice)
  ─ CORS — only Node backend URL allowed
  ─ Request body size limit 1MB
  ─ asyncio.Lock on model inference (prevents race conditions)

  Compliance & Audit
  ─ IP hashing (SHA-256, GDPR Art.5)
  ─ Immutable audit logs (cannot modify or delete)
  ─ Activity logs for all user events
  ─ GDPR right to erasure on account delete
  ─ Auto-delete banned users after 30 days (cron)
  ─ Cron cluster guard (runs on master only)

  Admin Controls
  ─ Role-based access (isAdmin middleware)
  ─ Cannot delete last admin
  ─ Cannot self-delete
  ─ Ban blocks user instantly on next request
  ─ Force logout any user

9. PASSKEY FEATURE — COMPLETE FLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  REGISTRATION (from Security Tab, must be logged in)
  ─ POST /api/passkeys/register/start  → challenge issued, stored in cookie
  ─ Browser biometric/PIN prompt
  ─ POST /api/passkeys/register/finish → credential saved, label auto-set
  ─ Label auto-generated from User-Agent (e.g. "Chrome on Windows")
  ─ Duplicate device check: same deviceName blocked with friendly error
  ─ Max 5 passkeys per user (pre-save hook on Passkey model)
  ─ Activity logged: PASSKEY_REGISTERED

  LOGIN (from /passkey-login page)
  ─ User types email
  ─ POST /api/passkeys/login/start  → challenge issued
  ─ Browser biometric/PIN prompt
  ─ POST /api/passkeys/login/finish → JWT issued (same as normal login)
  ─ Replay attack counter updated
  ─ If no passkeys: 404 + amber warning box with hint to add from Dashboard
  ─ Activity logged: PASSKEY_LOGIN or PASSKEY_LOGIN_FAILED

  MANAGEMENT (Security Tab)
  ─ View: device icon, label, deviceName, last used, date added
  ─ Rename: inline edit (Enter to save, Escape to cancel)
  ─ Delete: user can remove any passkey (e.g. lost device)
  ─ "Continue with Passkey" button always visible on Login page

  RULES
  ─ Max 5 passkeys per user
  ─ Only label is editable (cryptographic key is immutable)
  ─ User can delete their own passkeys
  ─ Admin cannot manage passkeys (only cascade-deleted with user)
  ─ Passkeys auto-cascade deleted when user account is deleted

11. HOW TO RUN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Backend (Node.js)
  ─────────────────────────────────────────────────────────────────────────────
    cd backend
    npm install
    node index.js          # or: npm run dev

    Health check: GET http://localhost:5000/api/health

  Frontend (React)
  ─────────────────────────────────────────────────────────────────────────────
    cd frontend
    npm install
    npm run dev

    Opens: http://localhost:5173

  AI Microservice (Python)
  ─────────────────────────────────────────────────────────────────────────────
    cd ai_microservice
    pip install -r requirements.txt
    uvicorn main:app --host 0.0.0.0 --port 8000

    OR with Docker:
    docker build -t ai-microservice .
    docker run -p 8000:8000 --env-file .env ai-microservice

    Health check: GET http://localhost:8000/health
    API docs:     GET http://localhost:8000/docs
